# router-relay

[English](README.md) | **Русский**

Локальный OpenAI-совместимый релей (`/v1`) без зависимостей, который позволяет
пользоваться роутером, не умеющим корректно завершать SSE-поток, из стриминговых
клиентов вроде Cline CLI и агента Hermes.

```
клиент ──SSE──▶ 127.0.0.1:8765 ──JSON (stream:false)──▶ роутер ──JSON──▶ релей ──корректный SSE──▶ клиент
```

## Зачем это нужно

Вышестоящий роутер (`router.cheap` / `direct.router-cheap.com`) принимает
стриминговые запросы, но никогда их не завершает: он присылает чанки с контентом, а
затем обрывает соединение — без чанка с `finish_reason` и без `data: [DONE]`.

Cline всегда работает в стриминге (он вызывает `streamText` и не имеет запасного
нестримингового пути), поэтому показывает:

```
Error: Failed to process successful response: TypeError: The socket connection was
closed unexpectedly. ... (ECONNRESET)
```

Тот же роутер отвечает безупречно, если попросить его с `"stream": false`: полное
сообщение, корректный `finish_reason` и блок `usage` приходят одним JSON-телом.

## Что он делает

Релей слушает `127.0.0.1`, принудительно ставит `"stream": false` в запросе к
вышестоящему сервису, а затем отдаёт готовый ответ клиенту в том виде, который тот
ожидает:

| Клиент прислал | Релей отвечает |
|---|---|
| `"stream": true` | **Корректным SSE-потоком**: дельта `role`, дельты `reasoning_content`, дельты `content`, дельты `tool_calls`, финальный чанк с `finish_reason` (и `usage`, если он есть), затем `data: [DONE]`. |
| `"stream": false` или поле отсутствует | **Одним JSON-объектом** (`object: "chat.completion"`). |

Нужны оба режима. Стриминговому клиенту (Cline, ход агента в Hermes) нужен SSE, а
нестриминговый клиент (вспомогательные вызовы Hermes — умные подтверждения,
генерация заголовков, сжатие, работа с изображениями) разбирает тело как один
JSON-объект и ломается на SSE-потоке с
`AttributeError: 'str' object has no attribute 'choices'`. Стримингом считается
только явный `"stream": true`: OpenAI-совместимый клиент, который не указал поле,
запрашивает поведение по умолчанию, то есть без стриминга.

Модель берётся из входящего запроса, поэтому клиент может свободно переключать
модели (либо зафиксируйте одну флагом `--model`). Поле `stream_options` удаляется
перед запросом к вышестоящему сервису, потому что без стриминга оно бессмысленно.

## Требования

- **Node.js 18 или новее** — релей использует глобальный `fetch`, `AbortSignal.timeout`
  и префикс модулей `node:`. Зависимостей npm нет.
- **`curl.exe`** — только если задан `proxy=`, потому что `fetch` из Node действительно
  игнорирует `HTTP_PROXY`/`HTTPS_PROXY`, и для построения туннеля используется curl.
  Уже присутствует в Windows 10 1803+ и в большинстве дистрибутивов Linux.
- Windows PowerShell 5.1+ или PowerShell 7+ — для опциональных скриптов запуска.

## Быстрый старт

```powershell
# 1. Создать локальный конфиг из шаблона и заполнить своими значениями.
Copy-Item conf.example.txt conf.txt

# 2. Запустить релей.
node router-relay.js --port 8765

# 3. Проверить, что он жив (выводит список маршрутов failover и остывающие маршруты).
curl http://127.0.0.1:8765/health
```

Затем направьте любой OpenAI-совместимый клиент на `http://127.0.0.1:8765/v1` с любым
фиктивным API-ключом — релей всегда авторизуется на вышестоящем сервисе ключом из
`conf.txt` и игнорирует то, что присылает клиент.

Разовая проверка без клиента:

```powershell
curl.exe -s http://127.0.0.1:8765/v1/chat/completions `
  -H "content-type: application/json" `
  -d '{"model":"your-model-id","messages":[{"role":"user","content":"Say OK"}]}'
```

## Конфигурация

`conf.txt` лежит рядом с `router-relay.js` и читается построчно в формате `ключ=значение`.
Пустые строки и строки, начинающиеся с `#` или `;`, игнорируются.

| Ключ | Значение |
|---|---|
| `base_url` | Основной адрес вышестоящего сервиса, вместе с `/v1` (например `https://router.cheap/v1`). |
| `base_url_reserved` | Резервное имя хоста — дополнительный маршрут для failover. |
| `api_key` | Bearer-токен, отправляемый вышестоящему сервису. |
| `model` | Читается `Start-Cline.ps1` для настройки изолированного профиля. Сам релей берёт модель из запроса, если не передан `--model`. |
| `proxy` | Необязательный локальный HTTP-прокси (например `http://127.0.0.1:10809`). Пусто = напрямую. |

> **`conf.txt` находится в `.gitignore`.** В репозиторий попадает только
> `conf.example.txt`. См. [Безопасность](#безопасность).

## Эндпоинты

| Метод | Путь | Поведение |
|---|---|---|
| `POST` | `/v1/chat/completions` | Транслируется на вышестоящий роутер; SSE или JSON, как описано выше. |
| `GET` | `/v1/models` | Пробрасывается на вышестоящий роутер (таймаут 30 с). |
| `GET` | `/health`, `/` | Локальная проверка живости. Возвращает `ok`, `upstream`, `upstream_reserved`, `proxy`, `routes`, `cooling` и `pid`. |

Именно `/health` опрашивают скрипты запуска, прежде чем стартовать клиента, поэтому он
должен отвечать даже когда все вышестоящие маршруты недоступны.

## Справочник по CLI

```
node router-relay.js [--port 8765] [--host URL] [--host-reserved URL] [--key KEY]
                     [--model ID] [--conf path] [--proxy URL] [--log FILE] [-v]
```

| Флаг | Псевдоним | По умолчанию | Значение |
|---|---|---|---|
| `--port` | `-p` | `8765` | TCP-порт на `127.0.0.1`. |
| `--host` | `-b` | `conf.txt` `base_url` | Переопределить основной адрес. |
| `--host-reserved` | `-B` | `conf.txt` `base_url_reserved` | Переопределить резервный адрес. |
| `--key` | `-k` | `conf.txt` `api_key` | Переопределить API-ключ. |
| `--model` | `-m` | модель из запроса | Зафиксировать модель, игнорируя запрос клиента. |
| `--conf` | | `<каталог скрипта>\conf.txt` | Альтернативный файл конфигурации. |
| `--proxy` | | `conf.txt` `proxy` | Переопределить адрес прокси. |
| `--log` | | нет | Дописывать диагностику в файл. |
| `--verbose` | `-v` | выкл. | Дублировать диагностику в консоль. |
| `--help` | `-h` | | Напечатать заголовочный комментарий скрипта. |

Без хоста и ключа релей не стартует (код выхода `2`), а если порт уже занят —
завершается с кодом `3`.

## Устойчивость

Релей рассчитан на то, чтобы переживать сломанные запросы, а не перезапускаться после них.

**Failover по транспорту и хостам.** Вышестоящий сервис стоит за Cloudflare и может быть
недоступен из некоторых регионов (блокировка или challenge), а локальный прокси точно
так же может лежать. Вместо выбора одного варианта каждый запрос обходит
упорядоченный список маршрутов, построенный как `хост × транспорт`:

```
base_url            напрямую
base_url            через прокси
base_url_reserved   напрямую
base_url_reserved   через прокси
```

Напрямую идёт первым, потому что это самый быстрый путь (~80 мс на TLS против ~300 мс
через прокси) и он не зависит от работоспособности прокси. Прокси идёт сразу следом,
потому что когда Cloudflare блокирует регион, все прямые хосты отказывают
одновременно — оба имени хоста находятся в одной зоне. Резервный хост всё равно
перебирается — для случая, когда проблема с одним именем хоста, а не со всей зоной.

Весь список проходится **дважды** (`ROUTE_PASSES = 2`), потому что роутер ещё и сам
по себе сбоит независимо от выбранного маршрута.

**Что запускает failover.** Ошибки транспорта и статусы `403` / `408` / `429` / любой
`5xx`. Статусы `400` / `401` / `404` возвращаются сразу, потому что ошибка на стороне
вызывающего воспроизводится одинаково на любом маршруте, и повторять её — значит лишь
впустую расходовать бюджет failover. Если все маршруты вернули одну и ту же ошибку
периметра, клиенту зеркалируется последний реальный ответ, чтобы он увидел настоящий
статус, а не придуманную релеем ошибку.

**Остывание с экспоненциальной задержкой.** Заблокированный маршрут отказывает не
сразу: соединение, сброшенное Cloudflare, может проявляться ~19 секунд, и платить это
время на каждом запросе было бы хуже, чем тот простой, от которого оно защищает.
Поэтому отказавший маршрут отправляется в «угол» — `60 с` с удвоением за каждую
подряд идущую неудачу, но не более `15 мин` — а здоровые маршруты пробуются первыми.
Остывающий маршрут никогда не выбрасывается: если здоровые тоже откажут, обходятся и
остывающие. Счётчик сбрасывается при успехе, поэтому восстановившийся прямой путь
возвращается сам.

**Защита на уровне процесса.** `unhandledRejection` и `uncaughtException` логируются
вместо убийства процесса (иначе Node ≥ 15 завершался бы посреди ответа — именно так это
и проявлялось как `ECONNRESET` в Cline). Исчезнувшие клиентские сокеты терпимы, каждый
путь обработки запроса обёрнут, а ответ `200` без `choices` превращается в честный
`502`, а не переигрывается как пустой ответ.

Таймаут одной попытки — 10 минут, потому что рассуждающие модели могут думать долго.

## Скрипты запуска (Windows)

Оба скрипта поднимают релей, если тот не отвечает на `/health`, и затем передают
управление клиенту.

### `Start-Cline.ps1`

Запускает Cline CLI против роутера на **отдельном профиле**, поэтому провайдер, которым
вы обычно пользуетесь в Cline (его модель, ключ и базовый URL), остаётся ровно таким,
как был, и обычная команда `cline` продолжает им пользоваться.

- Профиль живёт в `<каталог скрипта>\cline-router\data` и передаётся CLI как
  `--data-dir`. Сессии, логи и выбор провайдера остаются там.
- *Каталог конфигурации* остаётся по умолчанию `~\.cline`, поэтому глобальные правила /
  навыки / хуки / воркфлоу по-прежнему общие. Список глобальных MCP-серверов тоже
  общий — через `CLINE_MCP_SETTINGS_PATH`.
- Профиль использует собственный id провайдера `oi-router`, а не встроенный
  `openai-compatible`, потому что Cline игнорирует записи `models.json` для встроенных
  провайдеров. Без этого в статус-баре было бы `$0.00`, а размер контекстного окна
  остался бы неизвестным.
- Метаданные модели (контекстное окно, максимум входа/выхода, цены) копируются из
  `models.json` профиля по умолчанию при каждом запуске, поэтому совпадают с тем, что
  использует обычный `cline` для той же модели. Профиль по умолчанию только читается.

| Параметр | По умолчанию | Значение |
|---|---|---|
| `-Workspace <каталог>` | текущий каталог | Передаётся CLI как `--cwd`. |
| `-RelayPort <порт>` | `8765` | Порт локального релея (общий с `Start-Hermes.ps1`). |
| `-ProfileDir <каталог>` | `<каталог скрипта>\cline-router` | Корень изолированного профиля. |
| `-SyncProvider` | выкл. | Принудительно перезаписать профиль из `conf.txt` и метаданных модели профиля по умолчанию. Идемпотентно; запускайте после правки `conf.txt` или смены `-RelayPort`. |
| `-NoRelay` | выкл. | Направить профиль прямо на `conf.txt` `base_url`. Роутер не завершает SSE-потоки, поэтому длинные ответы будут падать с `ECONNRESET` — только для отладки. |
| `-UsePublic` | выкл. | Вместе с `-NoRelay`: использовать `base_url_reserved` вместо `base_url`. |
| `-NoSharedMcp` | выкл. | Не делиться файлом глобальных настроек MCP с изолированным профилем. |
| `-Status` | | Показать профиль роутера и профиль по умолчанию, затем выйти. Только чтение. |
| `-StopRelay` | | Остановить работающие процессы релея и выйти. |
| `-ClineArgs` | | Остальные аргументы передаются в Cline CLI без изменений. |

```powershell
.\Start-Cline.ps1                          # TUI на профиле роутера
.\Start-Cline.ps1 -Status                  # показать провайдера, модель, контекст, цены
.\Start-Cline.ps1 --yolo "run the tests"   # разовый запуск без интерфейса
.\Start-Cline.ps1 -StopRelay               # остановить релей
```

### `Start-Hermes.ps1`

Поднимает релей, если нужно, предупреждает, когда локальный порт прокси не слушается,
и запускает `hermes.exe`, передавая все аргументы дословно.

| Параметр | По умолчанию | Значение |
|---|---|---|
| `-SkipRelayCheck` | выкл. | Не трогать релей — просто запустить Hermes. |
| `-RelayPort <порт>` | `8765` | Порт для проверки/запуска. |
| `-HermesArgs` | | Остальные аргументы передаются в Hermes CLI без изменений. |

```powershell
.\Start-Hermes.ps1                      # открывает TUI Hermes
.\Start-Hermes.ps1 doctor               # собственная проверка конфигурации/зависимостей Hermes
.\Start-Hermes.ps1 -z "Reply with exactly: OK"
```

> Оба скрипта предупреждают, если порт прокси (`10809` по умолчанию) не слушается,
> потому что при заданном `proxy=` релею нужен он для доступа к роутеру.

## Структура репозитория

```
router-relay.js        релей (один файл, без зависимостей)
Start-Cline.ps1        скрипт запуска Cline CLI на изолированном профиле
Start-Hermes.ps1       скрипт запуска Hermes Agent CLI
conf.example.txt       шаблон конфига — скопируйте в conf.txt и заполните
.gitignore             держит conf.txt, изолированный профиль и логи вне git
.gitattributes         LF для кода/конфига, CRLF для PowerShell
README.md              документация на английском
README.ru.md           этот файл (русский)
```

Создаётся во время работы и намеренно **не** коммитится: `conf.txt`,
`cline-router/`, `*.log`.

## Безопасность

- `conf.txt` содержит действующий API-ключ и находится в `.gitignore`. Никогда не
  коммитьте его; используйте `conf.example.txt` как шаблон.
- Изолированный профиль Cline (`cline-router/data/settings/providers.json`) хранит тот
  же ключ открытым текстом, а сессии чатов в `cline-router/data/sessions/` могут
  содержать тела запросов. Весь каталог в `.gitignore`.
- Релей слушает только `127.0.0.1` и не проверяет учётные данные клиента — любой, кто
  может достучаться до порта, потратит вашу квоту на вышестоящем сервисе. Не
  выставляйте его наружу.
- Если ключ когда-либо попадал в коммит или был передан кому-то, перевыпустите его у
  провайдера.

## Заметки

- `-SyncProvider` перечитывает `conf.txt` и переприменяет его (теперь на URL релея).
- `-StopRelay` останавливает релей и выходит; `-RelayPort 9000` использует другой порт.
- `-NoRelay` (опционально с `-UsePublic`) ходит в роутер напрямую — только для
  сравнения, поскольку стрим там сломан.
